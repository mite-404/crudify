# Audit logging

Crudify can persist an audit record for every HTTP request. Logging is **opt-in** and disabled by default.

## Enable audit logging

```ts
import { Module } from "@nestjs/common";
import { MongooseModule } from "@nestjs/mongoose";
import { CrudifyModule } from "ncrudify";

@Module({
  imports: [
    MongooseModule.forRoot(process.env.MONGODB_URI!),
    CrudifyModule.forRoot({
      audit: {
        enabled: true,
      },
    }),
  ],
})
export class AppModule {}
```

When `audit.enabled` is `true`, `AuditModule` registers `AuditInterceptor` as a global `APP_INTERCEPTOR`.

Equivalent shorthand:

```ts
CrudifyModule.forRoot({ audit: true });
```

Disable automatic logging:

```ts
CrudifyModule.forRoot({ audit: false });
// or
CrudifyModule.forRoot({ audit: { enabled: false } });
// or omit audit entirely
CrudifyModule.forRoot();
```

## What is audited

The interceptor logs **all HTTP requests**, not only routes generated by Crudify. This includes your custom controllers, `/health` and `/config`.

The built-in `/audit` controller is excluded with `@NoAudit()` so reading audit logs does not create new audit logs.

Requests excluded with `@NoAudit()` are not logged.

## Options

```ts
export interface IAuditOptions {
  enabled?: boolean;
  collectionName?: string;
  userExtractor?: (request: any) => string | null | undefined;
}
```

| Option           | Default      | Description                                                                 |
| ---------------- | ------------ | --------------------------------------------------------------------------- |
| `enabled`        | `false`      | Enables automatic request logging.                                          |
| `collectionName` | `audit_logs` | MongoDB collection used to store audit records.                            |
| `userExtractor`  | built-in     | Custom function that extracts the user identifier from the request object. |

### `userExtractor`

```ts
CrudifyModule.forRoot({
  audit: {
    enabled: true,
    userExtractor: (request) =>
      request.user?.id ??
      request.user?.email ??
      request.headers["x-user-id"] ??
      "anonymous",
  },
});
```

The function may return a string, `null` or `undefined`. `null`, `undefined` and an empty string are stored as `"anonymous"`.

If the extractor throws, the interceptor catches the error and stores `"anonymous"`.

### Default user resolution

When `userExtractor` is not provided, the interceptor checks:

1. `request.user` if it is a string or number.
2. `request.user._id`
3. `request.user.id`
4. `request.user.sub`
5. `request.user.email`
6. `request.userId`
7. `request.user_id`

The first value found is converted to a string. If nothing is found, the user is `"anonymous"`.

This works well when an authentication guard has already populated `request.user` before the interceptor runs.

## Stored record

```ts
export interface AuditLogRecord {
  user: string;
  action: string;
  entityId: string | null;
  details: Record<string, any>;
  createdAt?: Date | string;
}
```

### Example document

```json
{
  "_id": "6a6c0a1753210eef9724e001",
  "user": "694977f46f807ce321fda999",
  "action": "PATCH /api/finance/order/:id",
  "entityId": "6a6b3a0753210eef9724d6c7",
  "details": {
    "method": "PATCH",
    "url": "/api/finance/order/6a6b3a0753210eef9724d6c7",
    "payload": {
      "review": "Ok - Concordato condizioni di pagamento Ri.Ba 30 GG dffm",
      "job": []
    },
    "oldDocument": {
      "_id": "6a6b3a0753210eef9724d6c7",
      "review": "Ok - Concordato con cliente metodo pagamento Ri.Ba 30 GG dffm"
    },
    "statusCode": 200,
    "durationMs": 32
  },
  "createdAt": "2026-10-22T10:00:00.000Z",
  "updatedAt": "2026-10-22T10:00:00.000Z"
}
```

## `action`

`action` is a normalized string in the form:

```
METHOD /path/:param
```

Examples:

| Request                                      | `action`                              |
| -------------------------------------------- | ------------------------------------- |
| `GET /api/users`                             | `GET /api/users`                      |
| `GET /api/users/6a6b...`                     | `GET /api/users/:id`                  |
| `PATCH /api/finance/order/6a6b...`           | `PATCH /api/finance/order/:id`        |
| `DELETE /api/users/6a6b.../soft`             | `DELETE /api/users/:id/soft`          |
| `POST /api/users/bulk`                       | `POST /api/users/bulk`                |
| `GET /api/users?age[gte]=18`                 | `GET /api/users`                      |

The action includes the global route prefix when one is configured. Route parameter values are replaced with `:paramName`. Query strings are not included in `action`; they are kept in `details.url`.

## `entityId`

`entityId` is resolved in this order:

1. `request.params.id`, if present.
2. The response `_id` or `id`, if the response is not an array.
3. `null`.

Examples:

| Request                         | Response                         | `entityId`            |
| ------------------------------- | -------------------------------- | --------------------- |
| `GET /users/123`                | document                         | `"123"`               |
| `POST /users`                   | `{ "_id": "abc" }`               | `"abc"`               |
| `POST /users/bulk`              | array                            | `null`                |
| `PATCH /users/bulk`             | update result                    | `null`                |
| `GET /users`                    | `{ results: [...] }`             | `null`                |

## `details`

| Field         | Description                                                                 |
| ------------- | --------------------------------------------------------------------------- |
| `method`      | HTTP method, for example `PATCH`.                                           |
| `url`         | Original request URL, including the query string.                           |
| `payload`     | Request body (`request.body`).                                              |
| `oldDocument` | Document before a `PATCH`, `PUT` or `DELETE`, when it can be resolved.       |
| `statusCode`  | Final status code.                                                          |
| `durationMs`  | Time spent handling the request, measured in milliseconds.                  |
| `error`       | Present for failed requests: `{ name, message, statusCode }`.               |

### `oldDocument`

`oldDocument` is loaded before the handler runs for:

- `PATCH`
- `PUT`
- `DELETE`

It is captured only when:

1. The request has an `id` route parameter.
2. The controller exposes the `modelName` metadata created by `@Crudify`.
3. The corresponding model exists in the Mongoose connection.

This means `oldDocument` is available for Crudify controllers and missing for custom controllers that do not use `@Crudify`. Bulk routes and collection routes do not have an `id` parameter, so `oldDocument` is `undefined`.

The document is loaded with:

```ts
model.findById(id).lean().exec()
```

If loading fails (for example, an invalid ObjectId), the error is ignored and `oldDocument` is `undefined`.

### `statusCode`

For successful requests, Crudify uses:

1. The explicit `@HttpCode()` value, when present.
2. `201` for `POST` requests.
3. The response status code, normally `200`.

For failed requests, it uses the exception status, then `error.status`, then `error.statusCode`, then `500`.

## Failure handling

Audit logging must never break the original request:

- Audit write failures are caught.
- Errors are written to the NestJS `Logger` with the context `AuditInterceptor`.
- The audit write is fire-and-forget; the HTTP response is not delayed until MongoDB confirms the insert.

`oldDocument` is loaded before the handler and adds one read query to `PATCH`, `PUT` and `DELETE` requests when the model can be resolved.

## Excluding routes with `@NoAudit`

```ts
import { Controller, Get } from "@nestjs/common";
import { NoAudit } from "ncrudify";

@Controller("users")
export class UsersController {
  @NoAudit("GET/:id")
  @Get(":id")
  findOne() {
    // ...
  }
}
```

`@NoAudit()` supports method and class decorators.

### Exclude an entire method

```ts
@NoAudit()
@Get(":id")
findOne() {
  // ...
}
```

A wildcard is stored, so every request handled by this method is skipped.

### Exclude an entire controller

```ts
@NoAudit()
@Controller("internal")
export class InternalController {}
```

### Exclude selected actions on a controller

```ts
@NoAudit("GET/:id", "DELETE/:id")
@Controller("users")
export class UsersController {}
```

### Supported patterns

| Pattern                       | Matches                                                     |
| ----------------------------- | ----------------------------------------------------------- |
| `@NoAudit()`                  | Everything on the decorated method or controller.           |
| `@NoAudit("*")`               | Same as `@NoAudit()`.                                       |
| `@NoAudit("GET")`             | Every `GET` request.                                        |
| `@NoAudit("GET/:id")`         | Actions whose path ends with `/:id`.                        |
| `@NoAudit("GET /api/users/:id")` | Exact normalized action.                                 |
| `@NoAudit("/api/users/:id")`  | Path-only match; also performs a suffix match.              |
| `@NoAudit("findOne")`         | Matches the controller handler method name.                 |

### Matching semantics

Patterns are normalized before comparison:

- `GET/:id` is treated as method `GET` plus path `/:id`.
- `GET /api/users/:id` is treated as method `GET` plus path `/api/users/:id`.
- `GET` matches every `GET` action.
- A path pattern matches the exact action path or any action path ending with the pattern.

The suffix behavior makes `@NoAudit("GET/:id")` work regardless of the controller prefix or global prefix. Be aware that a broad suffix such as `/:id` can match multiple routes.

### Metadata

`@NoAudit` stores action strings in metadata. The interceptor combines exclusions from the controller class and the handler. If any pattern matches, the request is skipped.

## Reading audit logs

### `GET /audit`

Returns audit logs. It uses the same query parser as Crudify, so the following are supported:

- Filters (`user`, `action`, `entityId`, `details.*`, `createdAt`, etc.).
- `sort`.
- `skip`.
- `limit`.

By default, logs are sorted by `createdAt` descending.

```bash
curl "http://localhost:3000/audit?action[cont]=users&limit=20"
```

```bash
curl "http://localhost:3000/audit?user[eq]=694977f46f807ce321fda999&sort=-createdAt"
```

### `GET /audit/:id`

Returns one audit log by `_id` or `null` if it does not exist.

```bash
curl http://localhost:3000/audit/6a6c0a1753210eef9724e001
```

The `/audit` routes are available even when automatic logging is disabled. This allows manual log entries to be read.

## Manual logging with `AuditService`

`AuditService` is exported from the global `AuditModule` and can be injected anywhere.

```ts
import { Injectable } from "@nestjs/common";
import { AuditService } from "ncrudify";

@Injectable()
export class OrderService {
  constructor(private readonly auditService: AuditService) {}

  async approve(orderId: string, userId: string) {
    await this.auditService.log({
      user: userId,
      action: "APPROVE /orders/:id",
      entityId: orderId,
      details: {
        method: "APPROVE",
        url: `/orders/${orderId}`,
        payload: { approved: true },
        statusCode: 200,
        durationMs: 0,
      },
    });
  }
}
```

### `AuditService` API

```ts
class AuditService {
  log(record: AuditLogRecord): Promise<AuditLog>;
  findAll(query?: Record<string, any>): Promise<AuditLog[]>;
  findOne(id: string): Promise<AuditLog | null>;
}
```

`findAll()` uses `QueryParser.parse()` and sorts by `createdAt: -1` when no explicit sort is provided.

## Collection

The default collection is `audit_logs`. Override it:

```ts
CrudifyModule.forRoot({
  audit: {
    enabled: true,
    collectionName: "security_events",
  },
});
```

The generated schema uses Mongoose timestamps and creates indexes on:

- `user`
- `action`
- `entityId`

### TTL / retention

Crudify does not create a TTL index automatically. To keep the collection bounded, create one manually:

```js
db.audit_logs.createIndex(
  { createdAt: 1 },
  { expireAfterSeconds: 60 * 60 * 24 * 90 }
);
```

This example deletes audit records after 90 days. Adjust the value for your retention policy.

## Security and privacy

Audit records can contain sensitive data:

- `details.payload` is the full request body.
- `details.oldDocument` is the full document before an update or delete.
- `details.url` may contain query parameters.

Crudify does not redact passwords, tokens or other secrets automatically. Recommendations:

1. Exclude authentication and secret-handling routes with `@NoAudit()`.
2. Avoid logging routes that accept credentials in the body.
3. Protect `GET /audit` and `GET /audit/:id` with authentication and authorization guards.
4. Consider a custom service or a dedicated interceptor if you need field-level redaction.

## Disabling audit

```ts
CrudifyModule.forRoot({ audit: { enabled: false } });
```

This keeps the audit module, `AuditService` and `/audit` endpoints available for manual log entries, but does not register the global request interceptor.

To disable logging for specific routes, use `@NoAudit()`.
